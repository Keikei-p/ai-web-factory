# AI案件分析 仕様

## 目的

登録された案件を、制作仕様書を作れる状態へ整理する。

AIは顧客が提供していない事実を創作しない。推奨と事実を混同しない。

## AIへ送る情報

原則として制作判断に必要な情報だけを送る。

送信候補:

- 案件名
- 依頼内容
- サイト種類
- 制作目的
- ターゲット
- 必要ページ
- 希望デザイン
- 参考サイト
- 必要機能
- 掲載素材
- 希望納期
- 予算

原則送らない:

- 顧客のメールアドレス
- 電話番号
- 不要な個人名
- APIキー
- パスワード
- その他、制作分析に不要な秘密情報

必要になった場合だけ、人間が確認して送信対象を拡張する。

## AIの出力

AIの回答は自由文章だけではなく、構造化データとして保存する。

```json
{
  "summary": "",
  "purpose": "",
  "target": "",
  "requiredPages": [],
  "requiredFeatures": [],
  "designDirection": [],
  "cta": [],
  "seo": [],
  "responsiveNotes": [],
  "accessibilityNotes": [],
  "missingInformation": [],
  "customerQuestions": [],
  "productionNotes": [],
  "recommendations": []
}
```

## 絶対ルール

1. 入力にない会社情報、実績、料金、住所、人物情報を作らない。
2. 不明な情報は「不明」または `missingInformation` に入れる。
3. 顧客への確認が必要なものは `customerQuestions` に入れる。
4. AIの提案は事実ではなく `recommendations` として分離する。
5. 参考サイトの文章・デザインをそのままコピーしない。
6. 不要な機能を勝手に確定しない。
7. SEOキーワードを事実確認なしに「検索需要が高い」などと断定しない。
8. 納期や予算の実現可能性を断定せず、制作上の注意として示す。
9. 制作開始をAIが承認しない。
10. 顧客への連絡をAIが勝手に送信しない。

## 分析後のステータス

```text
新規
↓
AI分析中
├─ 必要情報が不足 → 情報不足
└─ 仕様作成に進める → 確認待ち
```

ステータス変更はAIの分析結果だけで重要判断を確定しない。必要に応じて人間が確認する。

## 制作仕様書へ渡す内容

AI分析が確定したら、以下を仕様書生成へ渡す。

- 確定している事実
- 顧客要望
- 承認済みの推奨案
- 未確定事項
- 禁止事項
- 制作上の注意

未確定事項は仕様書でも未確定のまま保持する。

## AI接続前の確認事項

- 利用するAIプロバイダー
- API料金
- データ利用・保持条件
- APIキーの保存方式
- 1案件あたりの送信量
- 再分析時のバージョン管理
- エラー時の再実行方針

これらを確認し、ユーザー承認後にAI APIを有効化する。
